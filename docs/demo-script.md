# Verbal Demo Script (For Recruiter / Reviewer Presentation)

**Presenter Persona:** Forward Deployed Engineer (FDE)  
**Audience:** Razorpay Engineering Hiring Team & Operations Stakeholders  
**Target Duration:** 3 Minutes  

---

### [0:00 - 0:20] The Merchant Problem
*"Hi everyone. Today I'm demonstrating **MerchantOps Connector**, an operational gateway built for Razorpay Agent Studio.*

*Merchants already possess all the data they need inside systems like WooCommerce. However, autonomous agents cannot reliably query raw WooCommerce APIs: payloads are bloated, context windows get exhausted, rate limits cause crashes, and most critically—raw APIs don't correlate orders with inventory.*

*MerchantOps Connector solves this by turning WooCommerce into a bounded, read-only, agent-ready intelligence layer."*

---

### [0:20 - 0:45] Secure Connection & Guardrails
*(Action: Click "TEST CONNECTION" in the Left Panel)*

*"To guarantee safety, the connector operates under strict enterprise guardrails:*
1. *It requires only `Read` permission.*
2. *Mutations, refunds, and order deletions are blocked at the protocol level.*
3. *All user-supplied store URLs are validated against SSRF attacks and internal cloud metadata IPs.*
4. *We're currently running in zero-credential Demo Mode with 50 synthetic orders."*

---

### [0:45 - 1:25] The Differentiating Feature: Operational Attention Queue
*(Action: Click prompt "What orders need my attention today?")*

*"Now, let's ask the agent what needs merchant attention.*

*Notice what happened: the agent didn't run a simplistic SQL filter. It called `find_orders_needing_attention`, scanned active orders, and cross-correlated line item demands against live inventory levels.*

*Look at **Order #10482**: it is flagged as HIGH PRIORITY. The customer ordered 7 units of the Apex Pro ANC Headphones, but our warehouse inventory shows only 4 units on hand.*

*Critically, notice the language: the system states **'Potential fulfillment risk'**, not 'This order will fail'. As engineers, we provide calibrated operational signals, not hallucinated predictions."*

---

### [1:25 - 2:05] Ground-Truth Evidence Verification
*(Action: Click on Order #10482 to open the Evidence Inspector on the Right)*

*"Every single conclusion generated by the agent is backed by an explicit evidence chain:*
- *Evidence Source 1: WooCommerce Order API verifies 7 units requested.*
- *Evidence Source 2: WooCommerce Product API verifies 4 units in stock.*
- *Evidence Source 3: Inventory Snapshot records an exact 3-unit shortage.*

*In the right-hand panel, you can trace the exact execution lifecycle—from natural language parsing, to tool selection, to deterministic execution in 11 milliseconds."*

---

### [2:05 - 2:40] Deep Dive & Exploration
*(Action: Type "Show me all other orders affected by SKU-483")*

*"If an operations manager wants to drill deeper: 'Show me other orders affected by SKU-483'.*

*The agent executes `search_orders` filtered deterministically by SKU, retrieving Order #10491. Next, asking for 'the highest-value pending order' immediately surfaces Order #10415, an INR 29,998 order that has been stalled in pending for over 56 hours."*

---

### [2:40 - 3:00] Wrap-up & Engineering Rigor
*(Action: Open Audit Trail)*

*"Finally, our audit trail records every request ID, latency, and sanitized query. The entire system is covered by 40 automated tests with 100% pass rate.*

*This is what an FDE builds: an airtight operational connector that bridges real merchant systems with safe, bounded agent capabilities. Thank you."*
